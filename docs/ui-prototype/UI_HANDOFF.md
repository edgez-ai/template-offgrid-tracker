# 网页展示板与 App 接口交接

更新日期：2026-11-13。此文件描述当前展示板；以本目录的 README 和本文件为交接入口。

源码基线：此次交付基于上游 `b0b35eb1d98b1ea3cdc7fcb1a3ef39a17cfc9501` 建立独立分支。展示板最初对照本地 App 工作副本设计；其中 `RadioConfigModal.tsx` 属于本地 UI 实验，不在本次交付或上游基线中。下文涉及它的说明仅用于解释设计来源；生产能力应以本仓库受版本管理的 App、SDK 与固件为准。

视觉配色：黑白灰为主体，产品采用统一细线 SVG：项圈与耳标、聊天气泡、上下接口水阀、方形天线摄像头；正常状态与主要操作使用系统蓝，提醒与异常保留橙色和红色。示意地图使用灰白地块、淡蓝水域，深色主题采用相应深灰层级，不再使用绿色。

## 交付边界与打开方式

下载仓库后双击本目录的 `index.html` 或运行 `open_prototype.bat`。单独转交时请发送整个 `docs/ui-prototype` 文件夹：页面需要同目录的 `product-ui.css`、`product-ui.js`、`product-art.js`、`media.js`、`i18n.js`、`radio-catalog.js`，以及 `locales/base.js`、`locales/packs.js`。不需要安装依赖、启动服务或登录云平台。GitHub 的文件页只显示源码，需要下载后打开。

这是可操作的 UI 与状态规格展示板。所有节点、账号、回执和设备确认都是演示数据；没有调用 BLE、MQTT、Appwrite 或真实硬件。勿输入真实账号凭证或生产网络密码。地图是本地绘制的交互示意底图，不是真实地理瓦片。图片可本地选择、预览和加入会话；语音可选择本地音频、试听，并在浏览器允许时使用麦克风录制。真实媒体无线传输、实时对讲、真实地图下载和硬件控制尚未接通。

## 产品结构

- 根导航固定为“设备 / 我的”。首页的四张卡片是产品入口，显示产品类型、名称与基本状态。
- 项圈 / 耳标 → 牧场网关工作台 → 节点 / 地图 / 围栏 → 单节点详情。
- 聊天 → 公共信道 / 队友 → 文字、图片、语音会话。产品名称统一为“聊天”，仍对应独立固件设备，内部 target 标识 `radio` 保留以便接口映射。
- 水阀、摄像头只有入口卡片，点击提示详情未开放；没有控制或视频内页。
- 未来产品应根据明确的产品类型、实例 ID、固件标识及能力声明注册入口，不能用设备名称中的关键字猜测产品类型。

## 可操作流程与状态

展示板上方三种场景对应：未连接、控制设备已连接但没有远端节点、活跃网络。它们是演示预设，不代表全产品共用一条 BLE 连接。单独操作配对时，网关和手持机的连接状态分别更新。

项圈 / 耳标提供 8 个合成节点样本，包含低电压、过期位置、缺失定位、缺失电池和信号数据。支持按编号搜索、按状态筛选、重命名、单节点详情、地图缩放与拖动、地图节点选择。空值使用未知值；不伪造电池百分比、默认坐标、卫星数、活动或健康判断。

围栏提供圆形、椭圆、矩形、多边形。支持修改名称、中心、尺寸、旋转、顶点、适用节点、进入 / 离开提醒、启停、保存及删除确认。校验范围、UTF-8 容量、节点选择、至少一种提醒和多边形自交。节点位置与规则计算生成的是**当前样本的区域提醒**，不是对真实越界事件的确认。仅近期有效位置参与判断，未连接或数据过期时不推断“正常”。区域提醒可确认。

Chat 提供 5 个公共信道和队友会话，文字输入优先，图片与语音作为次级入口。图片支持本地文件选择、预览、可选说明和会话查看；语音支持音频文件选择、试听、浏览器麦克风录音、停止、重录与发送。拒绝麦克风权限时提示并保留文件选择路径，关闭或切换页面会停止麦克风轨道。图片类型限制为 JPEG / PNG / WebP / GIF。8 MB 文件上限、60 秒录音及 240 UTF-8 字节文字上限是展示板的保护限制，**不是固件能力承诺**，生产需重新协商。

公开广播只显示已发出，不声称全员送达或已读。私聊分别演示发送中、已发出、已送达、已读以及三次重试后失败。送达和已读为两个独立模拟回执；仅本机打开会话不会把自己发出的消息标为对端已读。下方演示选项可选择已读、仅送达或超时。手动重试更新同一条逻辑消息并保留媒体附件。

个人页支持验证码 / 密码两种演示登录方式。任意格式有效的演示邮箱可使用验证码 `123456` 或演示密码 `Demo@123456`，错误输入显示相应提示。密码仅用于当前页面演示，不写入本地配置。当前工程 `appwrite.config.json` 中 `email-password.enabled=false`，`email-otp.enabled=true`，客户端 `cloud-auth.ts` 也尚无完整密码登录入口；生产需要用户另行授权启用账号服务并实现对应客户端调用，本轮没有修改远端服务或生产 App。

添加产品进入附近设备搜索，而非类别列表。覆盖搜索中、发现设备、没有设备、蓝牙关闭和权限不足；可重搜并按选中的设备 ID 连接。演示预设中的两个设备分别为网关和聊天设备，扫描结果与配对均为模拟。生产应对接 `ProvisioningFlow` 的 BLE 扫描与安全握手，依据广播、服务与设备能力识别产品，而非根据用户名称猜测。**远端项圈 / 耳标由网关发现和管理，不伪装成手机可直接扫描到的 BLE 主控。**

围栏、昵称、节点别名、网络期望值和上次模拟应用值保存在浏览器 localStorage。账号、消息和媒体 Blob URL 只在当前页面会话保留，刷新后不会恢复媒体。浏览器存储受限时提示仅本页保留。退出账号不清除本地数据。

| 账号登录 | `CloudLoginModal.tsx` / `cloud-auth.ts` 邮箱 OTP | 连接真实验证码、密码验证及退出接口；当前密码认证在配置中被禁用，网页仅演示 |

## 围栏与后端的对应

现有云端包含 `geofence-areas`、`geofence-rules`、`geofence-alarms`，`function/src/main.js` 的 `evaluateGeofences()` 在收到有效位置遥测时执行。其几何判断有 circle、oval、rectangle、polygon 四种分支。本地 UI 实验的旧围栏按钮只是 Toast；不能据此认定上游 App 已接通创建、规则编辑或告警。

展示板 fence 对象需拆分为：

- 区域：`profileId`、`name`、`shape`、`geometry`。geometry 包含 `center` 与对应的 `radiusMeters` / `radiusXMeters`、`radiusYMeters` / `widthMeters`、`heightMeters` / `vertices`；旋转字段为 `rotationDegrees`。
- 规则：`profileId`、`name`、`areaId`、`deviceIds`、`enterAlert`、`exitAlert`。展示 ID 必须转换为该存储端认可的设备 ID。当前云端空 deviceIds 表示整个 Profile 的设备，**不保证仅限当前网关**，需要明确作用域。
- 启停：展示板 `enabled` 当前没有对应的已核实云端规则字段，需定义接口，不能直接丢弃。
- 告警：使用后端 alarm 的事件、触发时间、位置、active 和 acknowledged。展示板确认只修改本页状态，生产须补确认写入契约和权限。

云端判断、手机本地判断、网关独立判断是三种不同执行位置。纯离网条件下不能依赖云端函数。还需确认：规则存储位置与版本、下发与读回、后台能力、失联后行为、事件去重、GPS 漂移抑制、初次上报是否构成进入 / 离开事件。nRF 协议存在 `GeoFence` 定义，不等于已经有完整 App 执行链路。

## HaLow 配置的关键对齐

每个目标分别保存 `desired`（期望值）、`applied`（最近确认值）及状态。流程为编辑、校验、保存、下发、设备确认、读回比对。未连接只保存待应用；失败保留原确认值。切换目标不能让尚未返回的请求写到另一台设备。网关变更不代表子节点已完成迁移。生产需补请求 ID、配置版本、真实读回内容、重连与恢复机制。

展示板的目标绑定模型是设计契约，原 App 仍主要使用活跃 Profile 和共享 BLE 设备设置，需要同事实现多产品 / 多目标的对应，不能直接把当前单活跃 Profile 当作所有产品的全局配置。

已有保存字段：`country`、`halowChannel`、`meshId`、`meshPassphrase`。固件 ESP 配网使用 `passphrase`，SDK 初始化使用 `countryCode / meshBandwidthMhz / meshFrequencyKhz`；映射见 `ActiveProfileBleLink.tsx`、`ProvisioningFlow.tsx` 和 `firmware/main/halow_provisioning.c`。

国家、信道、频率和带宽必须作为一个合法组合联动，频率与带宽按固件表中的信道解析。Mesh ID 按固件缓冲区限制为 1–32 UTF-8 字节，密码允许空或 8–63 UTF-8 字节，不用默认密码覆盖用户留空值。网络密码不直接命名为“AES 密钥”。

本地 UI 实验 `RadioConfigModal` 的独立带宽、跳数和发射模式未进入其保存回调；上游 `ActiveProfileBleLink.tsx` 按国家和信道计算带宽。nRF 协议有 `max_hop`，仍需串通 SDK、存储、请求与确认。发射功率的现有 App 写入 / 读回链路尚未核实。展示板不提供这两个尚未接通的操作，交接时保留为明确的接口缺口。

### 最终联调验收

1. 以真实硬件测试未连接、已连空网络、多节点活跃，以及失联后的缓存标识。
2. 核对网关与所有子节点的身份、归属、信号链路、单位与各类时间戳。
3. 围栏的增删改、作用域、启停、告警与确认必须在选定执行端闭环。
4. 公共广播不能显示全员送达；私聊必须依据真实 ACK，掉线不假发送。
5. 网络参数完整写入、设备读回一致；失败可恢复，且不误改其他产品。
6. 账号与本地身份分别测试，登录退出不擅自改变离线数据或网络。
7. 在目标 Android / iOS 设备检查手势、安全区、键盘、触控区域和地图能力。

## 新增媒体与已读接口缺口

现有 `StoredMessage` 已有 `attachmentKind`、`attachmentName`、`attachmentMimeType`、`attachmentSize`、`attachmentFileId`、`voiceBytes`、`voiceCodec` 和 `durationMs`；固件 Mime 枚举包含 VOICE / IMAGE。它们表示协议存在类型，不等于完整的媒体发送、分片、重传、落库和播放链路已经实现。

- 展示板 `objectUrl` 是当前浏览器拥有的本地 Blob URL，只属于展示层，不能写成网络文件 ID。真实发送需协商编码、尺寸、压缩、分片大小、校验、取消、重传、进度和失败恢复。
- 浏览器 MediaRecorder 可能生成 WebM / Ogg / MP4 容器；不能直接把容器当作 SDK 要求的原始 Opus 数据塞入 voiceBytes。必须核对 codec 编号、容器、采样率及双方解码支持。
- 已读是新增的独立业务契约：建议包含 message UUID、阅读方身份、阅读时间，并验证身份及会话归属，支持幂等处理、断线补发。当前已核对的存储模型没有专用 readAt 字段，不能把 Operation.ACKNOWLEDGE 直接视为用户阅读。
- 展示板状态字段 `deliveredAt` / `readAt` 为拟接字段；生产中应由不同回执分别更新，并保留消息与重试的关联。广播的群体阅读状态需要另外定义，不能显示虚假的全员已读。
- 页面只修改网页原型。密码服务启用、真实 BLE 搜索、媒体传输、阅读回执和原生录音都需要 App 与固件同事联调，不应依据演示页面对客户承诺已实现。
